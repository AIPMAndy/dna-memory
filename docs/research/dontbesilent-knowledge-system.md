## 一页摘要

**最值得研究的并非“让 AI 一次读完千万字”，而是把零散内容变成有来源、有结构、有关系、有处理状态、能反复装配的生产资料。**

作者公开记录了两套不同的知识资产：

| 项目 | 来源、规模 | 数据结构 | 使用目标 |
| --- | --- | --- | --- |
| **公开推文原子库** | 累计 16,152 条推文；一轮处理 12,307 条，保留约 4,201 条实质性内容，产出 **4,176 条知识原子** | JSONL、来源 URL、发布日期、原文摘要、主题、类型、关联 Skill、置信度 | 回溯方法论，为 AI Skill 提供检索数据 |
| **本地内容结构化工程** | 作者公开披露原始 **143 个目录、2,330 个文件、约 1,293 万中文字符**；工程生成 **1,419 内容单元、223 主题地图、224 选题装配稿、1,720 条显式关系** | 原始素材副本、节点 Markdown、关系索引、主题地图、状态台账 | 让旧文稿、课程与案例不断服务新内容生产 |

**两套资产不是同一份数据库，4,176 不能简单加上 1,419 当作一个图谱的节点总量。** 私人大工程的统计来自作者自述与转录，未取得第三方审计其本机文件的证据。

## 2. 商业模式：内容获客与服务变现的组合

可以观察到的结构：

**商业问题诊断 → 内容传播 → 免费方法、公开工具与课程式解释 → 付费社群、线下课程等服务承接 → 经验再进入内容系统。**

- **公域**：X、抖音、小红书等内容平台。
- **免费资产**：dbskill 的公开使用入口与对应的内容方法分享。免费方法可成为可信度样本，但不能反推免费用户的付费转化率。
- **付费承接**：第三方样本记录“299 元答疑群”和线下课；价格存在时间边界，应以作者最新官方信息为准。
- **长期壁垒**：大量选题、表达经验、真实案例、业务判断被整理成能重复调用的节点；这是一种生产效率优势，而不是天然的收入保证。

商业公式应分开看：

有效商机 = 内容触达人数 × 符合客群比例 × 自愿咨询比例

收入 = 实际成交笔数 × 净收款额

利润 = 收入 − 内容制作、团队、人力、履约、退款、平台与技术等成本

没有实际成交及成本台账，不应宣称对方月入多少或断言其利润结构。

## 3. 千万字知识库怎么建？六层架构

~~~text
有权限的原始内容
  ↓ 只读审计、去除隐私和凭证、来源登记
原始材料副本 + 哈希 / 版本 / 台账
  ↓ AI 辅助提取，人工复核
QST 问题 / CON 概念 / OPI 观点 / CAS 案例 / SOL 方案
  ↓ 关系审查（回应 / 解释 / 证明 / 冲突）
主题地图 + 关系索引 + 去重候选
  ↓ 按明确读者和问题检索旧节点
选题装配稿（问题 → 判断 → 证据 → 解法）
  ↓ 人类审核与事实核查
新内容发布与效果复盘 → 新素材再次入库
~~~

### 3.1 原始材料绝不能被 AI 直接覆盖

原始文稿既是事实来源，也是日后校验结论的依据。正确做法是只读审计，登记原文、来源、作者、时间、完整性与权限，另建工程保存加工结果。

### 3.2 原子化：把“文件”转为“可回答问题的对象”

每条最小单元应包含：

- 稳定的节点 ID、节点类型、标题或知识陈述；
- 来源文件 ID、原文位置、可回溯的证据短句；
- 主题标签、处理与审核状态、版本信息；
- 已核验的关系，或待确认的关系候选。

五类节点分别承担不同功能：问题描述受众困境、概念解释术语、观点提出判断、案例提供证据、方案描述动作。不是每篇原文都必须硬拆五个节点，也不能没有证据就补案例。

### 3.3 知识图谱：不是把所有相似段落自动连线

可以有四类显式关系：“回应、解释、证明、冲突”。关系应指向真实存在的节点 ID；方向、关系类型与证据都要能复核。“同题”只是候选相关性，不等于“证明”。

**Obsidian 双链是展示层，而不是自动保证事实准确的机制。** 图数据库、向量数据库与云服务都不是第一阶段必备条件。

### 3.4 主题地图：让旧知识按用途聚合

例如“AI 求职获客”主题地图可连接：

- 问题：阅读很高但无人咨询；
- 概念：流量、有效线索、成交分母；
- 观点：明确客群比泛流量更重要；
- 案例：经授权、可复核的内容与咨询记录；
- 方案：页面承接、真实服务边界与转化漏斗测量。

上述是本文的**教学例子，不是 dontbesilent 的真实业务案例**。

### 3.5 选题装配：AI 组装，人判断

真正可用的装配稿应回答“给谁看、解决什么问题、哪条观点有证据、是否已经发过、下一步是什么”。Agent 负责查找、排列、去重及列出证据；人负责事实、商业判断、语言风格与发布。

### 3.6 处理状态：让工程能够持续增长

保存来源清单、已处理哈希、处理失败记录、重复候选、待审核节点、无效关系、发布反馈与版本。新增材料只处理变更部分，避免每轮从零重跑千万字。

资料：[dbs-content-system 官方 Skill 描述](https://github.com/dontbesilent2025/dbskill/blob/main/skills/dbs-content-system/SKILL.md)、[原始公开工程叙述](https://x.com/dontbesilent/status/2061724612753555590)（X 登录可能受限）、[转录归档](https://www.jxxy.net/ai/articles/dontbesilent-2b-tokens-content-system/)。

## 4. 为什么作者强调 Codex，而不是“一个超级 Prompt”

作者公开写到该工程耗时约两天、消耗约 2 亿 token，核心活动不是一次性总结，而是**Agent 在受约束的本地文件系统上反复操作、核验与调整**：

1. 确定输入、排除范围、输出目录和规则；
2. 建立工程目录、命名规范、来源与状态台账；
3. 从样本提取节点，校验节点类型与证据；
4. 建立关系、去重候选、主题地图和装配稿；
5. 运行验证、标记失败、修正后继续下一批。

“2 亿 token”只是其自述的资源消耗，不是用户复刻这项能力的必要预算。**先用 3—5 篇优质样本打通闭环，比盲目全量处理更优。**

## 5. 保姆级复刻：7 步可验收方案

| 阶段 | 执行动作 | 验收 |
| --- | --- | --- |
| 1. 资料审计 | 统计文件数、类型、敏感性，锁定纳入/排除目录 | 明确来源清单和权限 |
| 2. 原件保护 | 保留原文只读、生成哈希与来源 ID | 任何节点能跳回原文 |
| 3. 小样本抽取 | 3—5 篇文稿，提取 QST/CON/OPI/CAS/SOL | 无伪造案例，字段齐全 |
| 4. 审查与关系 | 人工核实观点、证据与有向关系 | 悬空关系为零 |
| 5. 主题地图 | 将同一主题节点聚合，保留来源 | 能可视化并打开节点 |
| 6. 装配稿 | 用已有节点生成新选题结构，不重新编案例 | 证据足够且能识别知识缺口 |
| 7. 增量更新 | 新文件只更新关联单元，旧版保留可追溯 | 无重复全量、状态可恢复 |

工程的最小可用目标不是 1,000 个节点，而是**回答一次真实业务问题，找回对应原文，组装出可审查的新内容**。

## 6. 我们的原创开源实现与边界

为避免直接搬运作者的受限作品，我在 [AIPMAndy/dna-memory 的 content-knowledge-graph 子项目](../../examples/content-knowledge-graph/README.md) 中采用**独立编写的 Python 标准库 MVP**，公开：

- Markdown/TXT 资料登记、敏感片段粗筛、哈希和来源；
- 离线显式标注提取，或用户明确授权后的 OpenAI-compatible API 语义提取；
- 五类知识节点、逐字证据和草稿审核；
- 手工确认的显式关系、错误检查、旧节点过期标记；
- 本地 HTML 图谱和选题装配稿。

这个项目并**没有**实现完整的大规模生产级系统；没有全文向量检索、复杂多源 PDF 解析或全自动关系真实性审核。公开仓库只含代码和虚构演示，绝不包含私人客户数据。

## 7. AI 酋长 Andy 的落地优先级

先把公开内容做成可复用资产，再扩展到受权限保护的经营知识，而不是把所有聊天和合同倒进去：

- **P0：公开内容资料**——X、Threads、小红书、公众号、公开 GitHub 项目说明，解决选题重复和引用来源问题。
- **P1：经授权的案例**——只含脱敏后可复核的事实与指标，用于内容证据。
- **P2：企业经营知识**——合同、报价、客户身份及内部数据独立隔离，默认不被内容创作 Agent 读取。
- **P3：内容效果数据**——在确保统计口径正确的前提下关联“主题 → 阅读 → 有效咨询 → 成交”，以实际转化代替空泛涨粉目标。

**首个可测任务**：从公开素材生成 3 篇未重复的 AI 求职或企业 AI 获客选题，每篇给出一条关键观点、至少一个真实可查来源、对应开源项目和证据不足项。用“有据可查、没有隐私泄漏、真实可用”作为放量门槛。

## 8. 核实、版权与风险

- 私人知识库的目录和成果规模来自作者公开披露；非第三方逐文件审计。
- 粉丝增长来自第三方平台观察，难以证明某单一策略直接造成增长。
- 没有公开可信的完整财务报表，不应编造营收、利润或付费人数。
- 官方 [LICENSE](https://github.com/dontbesilent2025/dbskill/blob/main/LICENSE) 自 2026-11-02 起对原创技能、源码、知识库等保留权利：允许特定个人安装、使用与设备上修改自用，但禁止未经许可再分发、打包、商业出售受限内容及 AI 训练。**私有仓库也不自动授予复制分发权**。
- 本文只引用公开事实、少量非侵权摘要与外链；所有代码自行实现，不重新打包 dbskill。
- 单纯使用公开社交帖子构建内容节点也要尊重隐私、平台规则、原作者版权和来源许可。
